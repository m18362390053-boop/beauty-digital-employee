## 2. 本轮查出的阻断及其修复范围

1. **第 0 段已修复用户网页加载阻断。** `web/customer/app.js` 原来引用了未提供的四个 `motion/*.js`，`index.html` 还引用了缺失的动效样式、`three.min.js` 和蝴蝶图片。现已移除失效依赖，保留原有非动效样式与交互，并增加用户页静态资源 404 的浏览器检查；没有伪造空的动效文件。
2. **2026-10-14 本地实测：**`npm test` **63/63 通过**；`npm run test:ui` **6/6 通过**。修复前浏览器为 3/6；旧文档“4 项通过”也属于更早版本。这些测试使用替身，不调用真实 Jev/DeepSeek，不能证明真实服务、产品资料或护理流程完成。
3. **组员反馈的统一失败文案不能只归因于阈值。** `providers.ts` 可能将低置信度导向追问；真正显示统一失败提示时，需查看当次 `status`、`warnings`、`route.reasonCodes`、`diagnostics.code`。实际是哪家模型、网络、格式还是引用出了错，必须用那条运行记录判断。
4. **视频入口不是视频 Skill 完成。** 当前接口不调用成片服务，也没有照片列表、撤回授权或删除接口；不要用真实个人照片长期测试后称“可随时删除”。

## 3. A1–A4 各自还要做什么

### A1｜可运行系统、语音服务与对接说明

- **已做：**本地后端、文字客服网页骨架、模型配置与现有客服接口；`README.md` 有启动方式。
- **已补：**用户网页移除缺失动效依赖，浏览器测试恢复 6/6。**未做：**提供电脑录音后把语音变文字的接口，以及把回复文字变成可播放音频的接口；后端保存语音服务密钥，网页和设备不接触密钥。
- **需要写给 C 的对接说明：**录音是什么格式、大小/时长限制、传到哪里；成功后返回转写文字还是错误；播报接口接收哪段文字、返回什么音频、失败时怎样只显示文字。服务商、模型名和音频格式应以实际测试定稿，不要把候选方案写成已接通。
- **完成标志：**网页可用；有人能在电脑上录一段真实中文，看到转写文字并核对，然后让系统回复并播放；拒绝麦克风权限、听不清或合成失败都能重试/改用文字。

### A2｜问答之外的护理流程和完成记录（最核心）

- **已做：**文字问答、客服知识引用、用户资料卡和客服运行记录。
- **已补演示版：**用户本人选择并确认虚构商品后，可用网页按钮或手打文字处理“开始、好了、重说、跳过、停止”；只有确认才记完成，运营端可查，误记可撤销。**未做：**B/D 正式核验的 2–3 个真实 SKU、按时段审核的固定计划，以及正式护理业务验收。演示版按用户选择的列表顺序执行，不是自动推荐真实产品搭配。
- **安全规则：**“重说”只重播当前步骤；“跳过”不算做完；“停止”不补写未完成步骤；同一次“好了”重发不能记两次。用量只引用该产品已审核的明确说明，没有依据就说“按包装说明取适量”。
- **完成标志：**不用语音和硬件，仅靠网页文字/按钮，就能把一个两步流程走完；数据库能查到正确的用户、产品、计划、步骤、时间和确认方式；重复点击、跨用户查看、跳过及停止都有测试。

### A3｜与 B/C 怎么对接（先约定，再接实物）

- **暂不做：**XIAO 的接线、烧录、无线连接和摄像头实际传输；这些由 B 负责。
- **A 先做：**提供一份双方都能读懂的**对接说明**，写清 B 发来按钮动作、或电脑录音经 A 的语音转写服务得到文字后，系统接收什么、做什么、返回什么；C 据此适配录音/播放展示。先用网页按钮和 HTTP 请求模拟，最后再接实物。
- **举例：**B 发“用户按了确认键”，并带本次操作的编号和当前流程编号；A 检查用户和步骤，最多记一次完成，然后回“已完成第 1 步，接下来第 2 步要显示/朗读的话”。A 的转写服务得到“好了”时应走**同一套护理判断**，不能另写一套可能记错的逻辑。
- **完成标志：**A/B/C 确认按钮种类、输入和返回字段、失败提示；模拟按钮和文字“好了”得到一致结果，未授权或重复请求不能修改他人记录。日后换成实物输入，不必重写护理流程。

### A4｜整体检查与交付

- **已做：**现有客服底座有自动测试、接口说明和运营端执行记录。
- **已补：**用户页与护理步骤/完成事件、按钮去重和跨用户隔离的自动测试。**未做：**真实语音、实物按钮和图像链路的联调证据；按真实产品/用户问句做业务验收、版本冻结与完整故障排查。
- **完成标志：**交付一个能实际操作的版本：确认产品 → 问“今晚先用哪瓶” → 一次只讲一步 → 说/点“好了” → 到下一步 → 查到完成记录；运营端能区分实际 Jev/Skill 调用、资料来源和护理记录。未联调硬件或视频要明确写“未验证”，不能靠页面文字或预录视频代替。

## 5. 怎样避免改坏组员的 Skill

- 尽量**新增**护理流程、语音和设备入口，不改变现有文字咨询请求 `{requestId, content}`、Skill 包格式或已保存的历史结果。
- 如果必须修改 `server/core/providers.ts`（Jev 选择）、`customer-service.ts`（调用流程）、`skill-packages.ts`（导入规则）、`workflow-types.ts`（数据格式），先与组员核对影响，再测“原来会选中/不会选中”的两个问题，以及停用和回滚后的行为。
- 每次看运营端的**实际 Skill ID、版本、知识来源和状态**，不能只凭前端回答或“上传成功”推断 Skill 已执行。阈值追问与模型失败要分别记录。
- 改数据库前先备份；当前根目录有未提交的团队文档和图片，先看 `git status`，不强制重置或覆盖。本文件只安排工作，尚未改应用代码或数据库。
