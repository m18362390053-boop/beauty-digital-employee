# 客服工作流、四页演示与模型配置

开发环境曾完成真实Jev＋DeepSeek Flash的单条冒烟联调。新克隆的项目不含密钥，需要按README自行配置；下文分别说明配置前后的行为。

## 不配置模型也能真实验证的流程

1. 启动后端，访问 `/demo/`，选择演示用户并新建会话。
2. 在“用户资料卡”保存偏好，回到客服页再创建新会话，查看记忆面板。
3. 输入“用了以后脸肿了，请转人工”。演示风险规则直接命中，状态变成等待人工，系统停止推荐。
4. 打开“人工接管”，展开摘要查看真实来源消息；点击接管，再输入一条人工回复。
5. 回到客服页，可见标为“人工坐席”的真实回复；AI继续暂停。
6. 对人工回复点击有帮助/没解决；看板统计更新。修改同一回复的反馈会替换原值。
7. 在坐席页结束接管，原会话变成已结束；继续咨询需新建会话。

普通咨询在没有密钥时明确返回降级模板，不能将其描述成Jev判断或模型生成。
所有样例资料标注为demo；现有风险短语和排除短语是测试起点，不代表已验证的业务安全分类器。

## 配置模型后的链路

后端所在终端设置 `TYPESAFE_API_KEY`、`CHAT_API_KEY`、`CHAT_BASE_URL`、`CHAT_MODEL`，或使用 `config/local.json` 的本地文件引用（详见README）。
`/api/status`只展示是否配置，不展示密钥；configured并不表示该密钥或模型已经验证有效。

`consult`：
1. 检查用户、会话、requestId和原文；相同请求重试返回原结果。
2. 先处理现有人工状态和明确风险规则。
3. 一次Jev请求判断意图、情绪、风险、主Skill、人工需求、信息充分性。
4. 高风险/人工优先，低确定性或信息不足追问，正常场景进入一个Skill。
5. 按Skill范围读取审核资料和最多20条评论，生成模型返回答案与来源ID。
6. 再次检查会话版本，保存答案、路由、模型版本、用量和引用。转人工后迟到的AI结果被丢弃。

真实模型效果需要组员金标验收。引用ID存在性已校验，但“该引用是否实际支持句子”仍需语义评测。
只在用户明确确认时更新资料卡；模型回复不会自动把猜测写入记忆。

## 新增HTTP接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 模型配置布尔值、策略版本、3个Skill定义 |
| POST | `/api/users/:userId/sessions/:sessionId/consult` | `{requestId, content}`，完整咨询 |
| GET | `/api/users/:userId/sessions/:sessionId/runs/:requestId` | 查询运行状态/原结果 |
| POST | `/api/users/:userId/sessions/:sessionId/handoff` | `{reason}`，暂停AI、创建/复用人工记录 |
| POST | `/api/users/:userId/messages/:messageId/feedback` | `{type, reason?}`，保存或替换反馈 |
| GET | `/api/handoffs` | 本地坐席队列 |
| GET | `/api/handoffs/:handoffId` | 摘要与状态 |
| POST | `/api/handoffs/:handoffId/claim` | 实际接管 |
| POST | `/api/handoffs/:handoffId/reply` | `{requestId, content}`，幂等人工回复 |
| POST | `/api/handoffs/:handoffId/resolve` | 结束人工处理 |
| GET | `/api/dashboard` | 两个统计分区及证据ID |

旧的 `POST .../messages` 仍然只是保存原话。需要业务处理时用 `/consult`。
本地坐席接口没有正式操作员认证，不通过用户MCP暴露claim/reply/resolve。

## 返回值如何理解

- `answered + generated`：生成模型实际返回并通过格式/来源检查。
- `degraded + template`：模型未配置、故障或返回无效，显示固定降级提示。
- `clarification_required`：缺信息、低确定性或无审核知识，不伪造答案。
- `handoff_pending`：进入队列，但真人尚未接管。
- `human_active`：本地演示坐席已点击接管。
- `interrupted/cancelled`：结果被人工状态或取消打断，不继续推荐。
- `routeStatus=rule_override`：代码规则命中，不宣称Jev执行过这次分类。
- `routeStatus=jev`：保留实际返回的模型、原始判断和token用量。

对同一requestId的错误或降级结果也会缓存。希望重新调用模型时，明确作为新请求发送新ID。
超时或断线不意味着没有写入，先查询runs接口；数据结果可在后端重启后读取。

## 看板口径

- 评论按唯一评论ID去重，标签可重叠；日期未知单独列，不用采集时间代替发布日期。
- 标签共现只是同一条评论同时出现标签，不是因果关系。
- 评论分区使用评论总数作为分母；客服会话分区按会话ID去重，历史最高风险单列。
- 有帮助率 = helpful / (helpful + unresolved)；request_human、未反馈排除，分母为0显示暂无。
- 原始案例/运行ID/评论ID可追溯。暂未做自由文本高频词分析及P95等高级指标。

## 启动与数据保护

升级前可执行 `npm run backup`，通过SQLite备份API处理WAL一致性，文件位于data/backups。
启动后schema自动由1升级到2，保留用户、会话和产品资料。
仅运行一个使用同一数据库的后端实例；启动恢复会将上次未结束的运行标记interrupted，防止重发付费请求。
现阶段没有自动重试付费API；429/超时显式降级，用户可稍后新建请求。
