# 用户端、运营端与Skill执行验收

> 本文的接口和权限规则仍可作说明；“已做的实际验收”是历史版本的记录。`4d6e46d` 上后端 63/63 测试通过，但浏览器只有 3/6 通过，用户端存在缺失静态资源。修复和复测前，不应把下文 4 项浏览器通过当作当前验收结果。见 [文档导航](README.md)。

## 两个入口

- 用户客服：`http://127.0.0.1:3090/chat/`
- 运营工作台：`http://127.0.0.1:3090/ops/`
- 根地址进入用户端；旧 `/demo/` 地址跳转运营端。

前端目录分别是 `web/customer`、`web/operator`，紫色主题放在 `web/shared`。两端共享一个后端与数据库。

## 运营登录

首次 `npm start` 自动生成本机 `data/operator-password.txt`，启动终端会显示文件位置，不打印口令。
在本机打开文件，复制口令到运营登录页。它与TypeSafe/DeepSeek的API Key无关。
也可在启动终端配置 `BEAUTY_OPERATOR_PASSWORD`（至少12字符），此时以环境变量为准。

- 运营会话有效期8小时；可退出登录，退出后原Cookie不再可用。
- 更换运营口令并重启后，旧运营会话失效。
- Cookie为HttpOnly、SameSite=Strict；写操作还校验CSRF。
- 本期是一套简化的运营身份，不是多坐席账号/企业权限平台。公网部署仍需HTTPS和部署配置。

## 用户身份与权限

用户首次打开客服页时，服务器创建随机匿名身份并绑定浏览器Cookie。用户端不提供userId选择、Key配置、Skill管理或原始路由JSON。

- 用户只能看、改自己的卡片和会话，并请求人工或提交反馈。
- 修改URL、额外传入userId、伪造角色头都不会获得他人数据或运营权限。
- 用户卡使用普通表单，不要求消费者编辑JSON。
- 技术错误、模型用量、内部风险/路由只给运营；用户得到友好的状态与重试/人工入口。
- 匿名身份有效期30天；清除Cookie或换浏览器会建立新身份，不支持跨设备找回。多人演示用不同浏览器环境或无痕窗口。

## 一次真实的双端流程

1. 运营登录，在业务配置里确认模型和产品资料就绪。没有数据时可初始化演示资料。
2. 用户打开 `/chat/`，保存自己的偏好并发送问题。
3. 运营打开“执行记录”，选择刚才那次运行，查看实际档案版本、决策来源、Skill版本和知识片段。
4. 用户点击联系人工，运营在人工队列中接管并实际回复。
5. 用户页收到标为人工客服的消息；该会话AI保持暂停。
6. 用户点击有帮助/没解决，运营在看板或执行记录的会话后续活动中核对。

运营“客服测试”是业务验收工具，可以选择测试用户；与公开用户端的身份绑定是不同入口。

## 可读执行证据

每次新咨询保存：收到请求、读取资料卡、调度检查、决策、加载Skill/知识、组织回复、保存结果等实际事件。
运营可以查看当时的：

- 用户卡快照及版本；
- Jev/规则/降级来源，业务意图、风险和分支原因；
- 被加载的Skill原文、版本；
- 提供给生成阶段的知识来源与片段；
- 回复状态、模型和用量；
- 会话当前人工状态、人工回复和反馈。

已加载文档不等于模型调用成功，请同时看阶段结果和实际模型字段。
旧版记录没有快照时明确标记，不倒填为“当时读取了现在的文档”。原始JSON仅在开发调试详情里展开。

## Skill文档与版本

进入运营端“业务配置 · Skill上传”：

1. 上传MD/JSON/ZIP后启用；下一条新请求使用注册表中的新版本。
2. 点击“当前Agent使用的Skill文档”查看当前说明和知识。
3. 点击“文档 / 历史版本”，预览指定版本的标准SKILL.md或导出ZIP。
4. 点击“启用此版本”恢复旧版本；如果另一位运营已经更新当前版本，会提示刷新，避免覆盖。
5. 旧请求保留自己的文档/知识快照，不受后续升级和回滚影响。

导出包包含manifest.json、SKILL.md、knowledge目录，并保留知识标题，可重新导入。
同版本不同内容禁止覆盖；上传、启停和版本切换都有记录。

“去测试实际选择”只设置前端待验证目标，不会强制Jev选择这个Skill。要检查正例、反例、停用后行为，并结合执行记录判定。

## MCP凭据

MCP不使用运营口令作为Bearer，而是使用只绑定某个用户的凭据。默认有效30天。

后端运行后，在项目目录：

```sh
npm run mcp:token -- --user demo-user-a
```

该命令使用本机运营口令向后端申请凭据，保存在 `data/mcp-credentials-demo-user-a.json`，不打印Token。
`start-harness.ps1` 已自动执行这一步，通常直接运行它即可。
手工运行MCP时设置 `BEAUTY_API_TOKEN_FILE` 或 `BEAUTY_API_TOKEN`；凭据不能改模型、上传Skill、读其他用户或执行坐席操作。

## API分层

- `/api/auth/customer/*`：建立/查看自己的匿名身份。
- `/api/customer/*`：Cookie绑定的本人数据，调用方不传userId。
- `/api/auth/operator/*`：运营登录、状态、退出。
- 原 `/api/settings`、`/api/skills`、`/api/handoffs`、`/api/dashboard`、`/api/ops/runs` 等：需要运营登录。
- 原 `/api/users/:userId/*`：允许运营，或只允许绑定该userId的MCP凭据；网页用户使用customer接口。
- `/health`：公开健康检查，不包含业务数据。

数据库schema为4。升级前可执行 `npm run backup`，保留用户、消息、资料和Skill版本。
所有运营口令、MCP凭据和数据库文件都在Git忽略范围内。
