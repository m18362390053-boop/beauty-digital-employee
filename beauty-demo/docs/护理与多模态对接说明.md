# 悦见护理与多模态对接说明（工程现状）

> 2026-10-14 本地未提交工作区。图片、ASR、TTS 的火山接口架构已增加，**无真实凭据/真实调用**，具体变量和限制以 [火山多模态接入](火山多模态接入.md) 为准。以下早期 DeepSeek 图片例子保留作为兼容入口，真实火山配置优先。设备实物联调暂不在此轮范围。

## 本地可以实际操作的流程

1. 运行 `npm run seed:demo` 导入两件**虚构演示**护肤商品（或在运营端点“初始化演示数据”），访问 `/chat/` → 开始咨询 → “一步一步做护理”。若已有数据库，仅向演示库导入缺失产品；真实业务库绝不可混入演示资料。升级已存在的 SQLite 数据库到 schema 6 前，先执行 `npm run backup`；原有会话/Skill 不会被新护理表覆盖。
2. 输入瓶身文字找候选，或主动授权拍摄/选取包装照片经已配置的火山方舟（旧 DeepSeek Flash 可兼容）读取可见文字。两种结果都**只作候选**；本人核对实物并确认商品。没有已审核用法的产品不能进入护理流程。
3. 页面一次展示一个步骤及来源；点“重说”不会推进，点“跳过”不会产生完成记录，“停止”直接结束。只有点“好了，完成这一步”或输入明确的“好了/完成”才写一条护理完成事件。UI 可撤销误记（事件保留撤销时间用于追溯）。同一请求编号重发返回同一结果；旧步骤的迟到确认被拒绝。
4. 演示商品的 morning/evening 只是标签，不代表已经审核真实商品方案。正式商品须先按 [正式商品审核计划模板](正式商品审核计划模板.md) 导入 B/D 实际核验的版本、时段、顺序和适用范围；不匹配或商品版本变化时返回 `CARE_PLAN_NOT_REVIEWED`。**目前尚无这份正式审核内容**。不能因为产品用法事实已审核就自动认定它适合任何时段或搭配。

## A 给 B 的按钮接入方式（已可调用，不是硬件联调完成）

由运营登录后调用 `POST /api/ops/device-credentials`，请求 `{ "userId": "当前要绑定的用户ID" }`，返回仅供该用户设备网关使用的 `token` 和 `expiresAt`；默认有效 7 天。它不是模型 Key，也不能访问运营端或普通客服资料。**仅交给本机网关，勿放入固件、网页公开脚本、日志或 Git。**目前服务默认监听 `127.0.0.1`；跨主机部署需要另外配置安全网关/HTTPS。
失窃或结束联调时，运营端可调用 `DELETE /api/ops/device-credentials/<userId>` 撤销该用户的**所有**设备网关凭据；下次联调需重新签发。

网关带 `Authorization: Bearer <token>` 调用 `GET /api/device/routines/current`，得到 `{ "routine": { "routineId", "status", "currentStep", "current", "steps", ... } }`。没有进行中的流程时 `routine` 为 `null`。用户先在网页确认产品并启动流程；设备**不能**绕过产品确认。

网关发按钮：`POST /api/device/routines/<routineId>/actions`：

```json
{ "requestId": "button-0001", "expectedStep": 0, "action": "confirm" }
```

`action` 只可为 `confirm`（好了）、`repeat`（重说）、`skip`（跳过）、`stop`（停止）。网关为每次真实按键生成唯一 `requestId`，网络重试保持**同一个**编号；`expectedStep` 使用上次返回的 `currentStep`。返回更新后的 `status`、`currentStep`、`current`（下一步及显示/朗读文字）、`steps`、`eventId`（仅 `confirm` 有值）。相同编号相同内容重试不会重复入库；同一编号换内容返回 409，同一按键在旧步骤迟到返回 `STEP_CHANGED`。网关收到 409 应重新获取 `current`、展示给用户确认，不能自动推进下一步。设备 token 只接受设备端接口，网页按钮不允许伪称设备来源。

## A 给 C 的文字/语音展示边界

网页现在可调用 `POST /api/customer/routines/<routineId>/text-commands`：

```json
{ "requestId": "utterance-0001", "expectedStep": 0, "text": "重说" }
```

目前输入的是**用户手打的文字**，仅识别固定指令“好了 / 完成 / 重说 / 再说一遍 / 跳过 / 停止”，成功后与按钮共用同一套步骤变化和记录规则；其他文字返回 `COMMAND_NOT_RECOGNIZED`，不修改步骤。网页请求需要用户 Cookie 及 `X-CSRF-Token`，不能携带其他用户 ID。

电脑短句录音链路已搭出接口：用户授权麦克风 → 浏览器转 WAV → 后端向已配置的火山方舟音频理解服务转写 → 页面只填入可修改草稿 → 用户亲自点击发送；不把未核对的听写直接当“好了”。业务系统返回的 `current.instruction` 可点击使用豆包语音合成朗读，失败仍显示原文。**无真实密钥、未验收听写和播报；C 的设备录音/播放、回声消除及连续语音仍未接。**变量和格式见 [火山多模态接入](火山多模态接入.md)。开发人员基础测试等待不超过两分钟是工作节奏限制，**不是产品超时参数**。

## 识图数据流边界

链路：网页端主动选取**仅含产品包装**的图片并授权 → 浏览器缩放并重新编码 → 后端优先调用已配置的火山方舟图片模型（否则兼容现有 DeepSeek Flash）提取可见文字 → 按完整导入名称做保守匹配，返回候选 → 用户确认后可创建绑定此商品的**新文字咨询会话**。模型回复不会直接创建护理计划或完成记录。B/C 的实物摄像头到电脑的采集/授权流程仍未联调。

`POST /api/customer/packaging/candidates` 保留纯文字匹配：`{ "observedText": "包装上看到的名称" }` → `{ "status": "confirmation_required", "recognition": "text_match_only", "items": [...] }`。

`POST /api/customer/packaging/recognize` 是图片入口；需当前用户 Cookie 与 CSRF，且显式同意把**本次**图片发给页面显示的服务商：

```json
{ "authorized": true, "image": { "mediaType": "image/jpeg", "dataBase64": "<仅本次图片的标准Base64>" } }
```

只接受内容与声明格式一致的 JPEG、PNG、WebP；单张解码后不超过 1MB（网页先压缩，网页原文件不超过 5MB）。后端不写图片文件/数据库；配置后照片会外发给所选服务商，**不能声称从未上传到外部服务**。响应含 `status: "confirmation_required"`、`recognition: "vision_model"`、`observed`、`items` 与说明；不返回“已确认”。无可靠匹配时返回空列表；未配置时 `VISION_NOT_CONFIGURED`。图片不得用于判断用户是否已涂抹。当前未用团队的实物样本或真实 API 测过准确率，模糊、多瓶、库外拒识需要真实验收。已有 `/api/customer/video-moments` **另行保存授权照片**，与此不落盘的产品认图入口不同。

用户可查询 `GET /api/customer/input/capabilities`：`typedText`、`packagingTextMatch`、`screenButtons` 是 `available`；`asr`、`tts`、`imageRecognition` 在未配对应环境变量时为 `not_configured`，配置后为 `configured_unverified`，**不是实际接通或准确率已验收**。图片入口另返回 `imageProvider` 供授权文案指明外发对象。语音接口和部署配置见 [火山多模态接入](火山多模态接入.md)。

## 护理接口汇总（已实现）

| 方法与地址 | 用途 |
|---|---|
| `GET /api/customer/routines/products` | 当前可用于演示护理的产品（仅有审核用法的虚构示例）。 |
| `POST /api/customer/routines` | `{ requestId, period: "morning" \| "evening", productIds: ["..."], confirmed: true }`；用户确认候选后的演示流程。 |
| `GET /api/customer/routines/current` | 恢复当前流程；`GET /api/customer/routines/<id>` 查指定本人流程。 |
| `POST /api/customer/routines/<id>/actions` | `{ requestId, expectedStep, action, source: "screen" }`；网页按钮。 |
| `POST /api/customer/routines/<id>/text-commands` | `{ requestId, expectedStep, text }`；用户手打指令。 |
| `GET /api/customer/care-events` | 本人最近 100 条完成事件，撤销项含 `voidedAt`。 |
| `DELETE /api/customer/care-events/<eventId>` | 撤销本人误记，不删除其他用户数据。 |

操作和完成记录存于 SQLite 的 `routine_runs`、`routine_actions`、`care_events`，不与原客服消息或 Skill 版本混用。护理步骤保存开始时的产品版本、已审核用法和来源快照；原客服 Jev/Skill 执行记录只证明当次**咨询**，不能冒称每个护理按钮都实际调用了 Jev。
运营端“护理记录”页面及 `GET /api/ops/care-events` 可查看最近 100 条确认事件、用户、来源版本与撤销状态；目前尚无护理动作（包括重说/跳过/停止）的完整可视化时间线。真实语音/图像调用证据仍待接入。
