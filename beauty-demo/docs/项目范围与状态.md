# 项目范围与团队交付

## 比赛范围

围绕一个产品、3个业务Skill、4类意图、3级风险，完成：
资料和匿名评论 → 用户卡 → Jev调度 → Skill回复 → 人工接管 → 反馈与看板。

团队目标数据：至少200条有效匿名评论、50条经业务确认的Case。
开发负责功能与验证工具，业务A提供评论及洞察，业务B提供产品知识、Skill内容、风险边界和金标。

## 已实现与验证

- 本地网页四个页面、数据存储与跨会话记忆。
- Jev与DeepSeek接口、可替换的Skill配置、风险优先策略。
- 人工接管状态、实际人工回复、AI取消与迟到结果拦截。
- 反馈替换、评论与会话统计分区、来源ID追踪。
- 10个MCP工具，支持Harness调用同一后端。
- 35项自动工程测试通过；本机浏览器完整流程已验证。
- 曾用真实模型完成单条端到端调用，并通过MCP重放同一结果。

## 待业务验收

- 正式产品资料、至少200条评论、3个Skill的审核内容。
- 用50条业务Case验证分类、追问、风险处理、知识依据和品牌语气。
- 置信度阈值和风险规则校准；当前demo配置不代表已达到线上效果。

## 后续技术细化

- CSV和独立洞察文件导入、自由文本高频词和更细的评测报告。
- 服务器部署、HTTPS、正式身份与坐席权限。
- 豆包等其他宿主实际接入验证；现阶段已交付HTTP/MCP接口。

## 数据与边界

仓库只提供虚构演示资料，不含真实密钥、运行数据库或个人会话。
医疗风险仅用于客服流程控制，不承担诊断。人工摘要保留原话供坐席核实。
无需自研/训练模型；通过业务内容、固定判断问题、执行策略和金标迭代。
