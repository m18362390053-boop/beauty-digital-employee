# XIAO ESP32S3 Sense 后续硬件架构（USB 本地版，设计草案）

> 2026-10-18：仅依据[Seeed 引脚复用说明](https://wiki.seeedstudio.com/xiao_esp32s3_pin_multiplexing/)、[麦克风教程](https://wiki.seeedstudio.com/xiao_esp32s3_sense_mic/)、[Waveshare 1.83 英寸屏资料](https://docs.waveshare.com/1.83inch_Touch_LCD_Module)及组员实物照片制定。**没有完成固件编译、接线、板上采样或显示/播放验收。**原始照片未提交；屏幕商品链接、功放芯片丝印与供电表仍待组员核对。不要按本草案直接上电。

## 目标与分工

```text
Sense 摄像头/麦克风 ── 采集 ──┐
触摸或外接按钮 ── 输入 ────────┤ XIAO 固件 ⇄ USB CDC ⇄ 电脑桥接 ⇄ 127.0.0.1 后端/SQLite
LCD/功放/喇叭 ← 显示/解码播放 ─┘                 │
                                             已配置的识图/转写/TTS 服务
```

- **板上**负责采样、限尺寸压缩/封包、按键防抖、屏幕显示、音频解码到 I²S、超时和断线提示；不存用户/模型凭据、护理计划或正式商品知识。
- **电脑桥接**独占 USB 串口，持有本机文件中的用户绑定设备 token；只接本机后端。未来媒体收发要单独加入逐次授权入口，不能直接复用只接受浏览器 Cookie/CSRF 的客服媒体 API；音频听写只能产生待人工确认的草稿。
- **后端**负责业务资料、用户绑定、审核计划/步骤记录以及外部模型调用。图像候选不自动确认 SKU，ASR 不自动执行“好了”，未审核真实 SKU 不启动护理。
- 已有的 [USB 第一阶段](../docs/ESP32S3-USB本地联调.md)只支持取步骤和“重说”；本文件是未来扩展的评审输入，不修改现有 v1 串口协议或数据库。远端组员新增的移动护肤日程/OCR 是另一条业务流程，接设备前必须明确归属，不能自动把日程勾选等同于护理完成事件。

## 引脚资源：已知事实与预留（不是接线表）

| 功能 | Seeed/实物可核对的资源 | 冲突与待核对项 |
| --- | --- | --- |
| Sense 板载 PDM 麦克风 | GPIO42 时钟、GPIO41 数据；扩展板 D11/D12 默认保留给麦克风 | 不切 J1/J2；不要与 `10PI-AMP&MIC V3` 的第二路 PDM `CLK/DAT` 并接。 |
| 摄像头 | Sense 扩展板 B2B；官方列出专用摄像头信号（如 GPIO10–18、38–40、47–48） | 排线看似 `OV3660`，需实物/驱动识别；不能照其他摄像头批次硬编码配置。 |
| microSD/TF | SPI D8/GPIO7(SCK)、D9/GPIO8(MISO)、D10/GPIO9(MOSI)，GPIO21(CS) | **暂不启用卡**。官方指出 J3 焊盘的上拉网络可能妨碍外接 SPI，不能仅靠不同 CS 就断言可与屏幕共存；不授权切割/焊改 J3。GPIO21 同时是用户 LED 信号，勿直接改用。 |
| 1.83 英寸 LCD 显示 | 实物丝印 `LCD_DIN/CLK/CS/DC/RST/BL`；与 Waveshare 同名 240×284 模块资料相符，其官方型号使用 SPI + ST7789P | **同名不等于确认同批 SKU/控制器**。外接 SPI 与 microSD/J3 存在实际冲突；屏幕至少还需 CS、DC、RST、BL 的资源与安全电平，不能先固定引脚。 |
| LCD 触摸 | 实物 `TP_SDA/SCL/RST/INT`；若核实为上述 Waveshare 型号，官方芯片为 CST816D，I²C 通常可考虑 D4/GPIO5(SDA)、D5/GPIO6(SCL) | SDA/SCL 只是候选分配；RST/INT 是否必接由实际模块驱动与实测决定，勿悬空后宣称可用。 |
| `10PI-AMP&MIC V3` 功放 | 板上 `LRC/BCLK/DIN` (I²S)、`GND`、`3.3V/5V` 与 PH2.0 喇叭口 | I²S 输出至少占 3 条合适 GPIO；供电能力、逻辑电平、功放芯片与扬声器负载阻抗仍须商家规格/丝印确认。不能把喇叭直接接开发板 GPIO。 |
| 外接“重说”按钮 | 第一阶段草案 D0/GPIO1 → GND | D0 已占一个普通 GPIO；后续触摸 UX 设计若替代按钮，先评估再调整固件。不要把 BOOT/GPIO0 当业务键。 |

**资源预算与决策门槛：**保留板载麦克风和摄像头之后，普通外露引脚 D0–D10 有限；LCD（SPI 两条数据/时钟 + CS/DC/RST/BL）、触摸（两条 I²C + 可能的 RST/INT）、功放（3 条 I²S）、按钮（1 条）加起来不能仅凭“支持 SPI/I²S/I²C”就假定能同时分配。先向组员索取 LCD 的购买链接/驱动型号、功放芯片近照/供电与喇叭参数、扩展板 J3 实物状态；由 B 画出**一张完整的 D0–D10 + GPIO21/41/42 引脚占用表**，每项标记电压、共享/独占和连线方向，再进行评审。不能默默修改 Sense J1/J2/J3 或让 5V 信号进入 3.3V GPIO。

如果 LCD 必须占用默认 SPI 而 J3/TF 妨碍通信，可供评审的路线为：①第一版**不插 TF 卡**并核验 J3 实际电气状态（不等于默认就能共存）；②取得 Seeed/屏幕驱动依据后验证可用的重映射或独立总线；③更换兼容的扩展/显示方案。切割焊盘只在评审、备份/可恢复方案与明确授权后考虑；本文件**不推荐现在切割**。

## 分阶段接口、验收证据与停止条件

| 阶段 | 代码/连接要点 | 必须留下的实物证据；失败时的保守退路 |
| --- | --- | --- |
| 1. USB 状态与重说 | 现有 v1 JSON 行协议；串口桥接仍只接受 `repeat` | 开发板 COM 或 `/dev/cu.usbmodem*`、烧录版本、一次 GET + 按键回执、断线重连；未通过不接外设。 |
| 2. LCD 单独验收 | 核实模块控制器/供电，屏幕先显示**固定测试字**再显示服务端 `current.instruction`；触摸单独读取坐标再设计 UX | 白屏、复位、中文渲染、方向、背光和是否影响 USB；失败仍通过电脑网页展示。未核对电平/引脚不通电。 |
| 3. 功放播放 | 核实功放和喇叭规格；先板上产生低音量测试音，再考虑电脑下发短音频；MP3 需在电脑或板上解码为 PCM 后送 I²S | 失真/发热/电源跌落与紧急停止播放；失败显示文字，不用 TTS 声称播报已可用。专用 TTS 凭据/音色仍需配置与真实验收。 |
| 4. Sense 麦克风 | 只启用**一路** PDM；先板上自录并确认 16 kHz/16 位/单声道 WAV，再设计 USB 分块上传与明确授权 | 时长、采样率、噪声、空语音、取消；本机音频不写公开日志，ASR 只填可修改草稿。 |
| 5. Sense 摄像头 | 用实物批次选择驱动；先本机 JPEG 拍摄/回看，受控压缩到后端允许的输入大小后再设计 USB 传输与逐次授权 | 暗光、糊图、库外品的拒识及用户确认界面；不能让拍照自动确定 SKU 或写入正式计划。 |
| 6. 合并外设 | 逐项增加 LCD+触摸、I²S、PDM、摄像头；验证并发内存、电源与 SPI/J3 | 留下冲突矩阵、短录/显示/播放/拍照的重启和超时记录；故障后降级为网页操作，不能丢/重复完成事件。 |

## USB 媒体协议 v2 的前置设计（尚未实现）

> 更新：已添加[一次性 USB 媒体试验](../docs/ESP32S3-USB图片与语音测试.md)（独立固件和脚本、按次同意），仅用于 JPG/WAV → 模型候选/草稿的短任务；下述可靠传输和统一固件方案仍属后续设计，**不表示实物已验收**。

v1 是 ≤1 KB 的 JSON 行，**不能把 base64 JPEG/WAV 塞进 v1 行**。v2 需独立握手和有界二进制分块（单任务 ID、模态、声明字节数、长度+顺序号、校验、ACK/超时、取消/结束），同一时刻限一个媒体任务；桥接在完整校验和授权通过前不得调用后端。设计预算须小于后端现行图片解码 **1 MB**、语音 **2 MB** 上限，并以实物 PSRAM/USB 吞吐测量调整。PC 上持有 token 和媒体授权，板上只保留有限缓冲；失败丢弃未完成任务，不把音频文字自动解释为护理操作。v2 实装前必须另行定义授权 UI 与隐私保留策略，不使用未确认的共享日程 token 或运营密码代替媒体权限。
